# Продуктивність і PageSpeed

Mobile PageSpeed головної піднято з 33 до ~90, `/ideas` з 62 до 90 ([#58](https://github.com/LitvinchukRoman/fantasm/pull/58)), без зміни дизайну. Цей файл пояснює, що тримає бал, які правила не можна порушувати і як перевірити зміну до мерджу. Прочитай його перед тим, як чіпати перший екран, шрифти, WebGL-фони, сторонні скрипти або `root.tsx`.

Ціль: **≥ 90 на mobile для `/` і `/ideas`**. Pull request, який опускає бал нижче, не мерджиться без окремого рішення.

## Чому PageSpeed бачить сайт інакше, ніж ти

PageSpeed (Lighthouse) емулює слабкий Android: CPU сповільнений у 4 рази, повільний 4G, і **немає GPU**. WebGL там рахує процесор через SwiftShader в основному потоці. Тому:

- бал однаковий для всіх відвідувачів і не залежить від їхнього пристрою. Це лабораторний тест;
- на Mac із GPU проблему не видно: той самий білд у звичайному headless Chrome дає від 35 до 85 балів;
- справжні користувачі видно окремо, у field data (Core Web Vitals за 28 днів) у верхній частині звіту PageSpeed.

| `/`, mobile | До #58 | Після |
| --- | --- | --- |
| Score | 33–36 | 89–91 |
| Total Blocking Time | 22 830 мс | 0 мс |
| LCP | 5.7 с | 2.9–3.0 с |
| FCP | 3.5 с | 2.4 с |
| Speed Index | 13.2 с | 4.4 с |

## Правила

### 1. Декоративний WebGL стартує лише на GPU і лише після завантаження

Головна причина 33 балів: three.js-сфера на головній у PageSpeed давала задачу в основному потоці на 10–36 с. Тепер `hero-background.tsx` і `grid-background.tsx` роблять так:

```ts
const cancelStart = whenIdleAfterLoad(async () => {
  if (!(await hasHardwareWebGL())) return; // показуємо CSS-фолбек
  import("./webgl/create-scene").then(/* ... */);
});
```

- `hasHardwareWebGL()` (`app/lib/webgl.ts`) перевіряє GPU у Web Worker. `failIfMajorPerformanceCaveat` ловить не все, тож додатково відсікаємо рендерери SwiftShader, llvmpipe і software (`app/lib/webgl-renderer.ts`).
- `whenIdleAfterLoad()` чекає `load`, перший кадр і вільний основний потік. Компіляція шейдерів синхронна і на телефоні займає сотні мілісекунд.
- Сцена завжди підвантажується динамічним `import()`. Тоді three.js не потрапляє в бандл першого екрана.

Не можна:

- імпортувати `three` або файл сцени статично з компонента сторінки;
- запускати сцену прямо в `useEffect` без `whenIdleAfterLoad`;
- переносити перевірку GPU в основний потік: створення WebGL-контексту блокує його на 0.9 с з GPU і до 8 с без GPU;
- робити новий WebGL-фон без CSS-фолбеку. Без GPU і з `prefers-reduced-motion` людина бачить саме фолбек.

### 2. Перший екран повністю є в SSR-HTML

LCP рахується від найбільшого тексту або картинки першого екрана. Раніше ним був текст cookie-банера, який з'являвся лише після гідратації, і LCP чекав увесь JS.

- Банер згоди (`app/components/ui/consent-banner.tsx`) є в серверному HTML завжди. Інлайн-скрипт `CONSENT_SNIPPET` у `root.tsx` до першого кадру ставить `html[data-consent]`, якщо вибір уже збережено, і CSS ховає банер (`app.css`).
- Видимий контент першого екрана не можна ховати за `useHydrated`, `useEffect` або клієнтським fetch. Якщо щось має з'являтися лише на клієнті, воно не повинно бути найбільшим елементом екрана.

### 3. Шрифти свої, з preload

Onest лежить у `app/fonts/` (woff2-підмножини Google з тими самими `unicode-range`, `@font-face` угорі `app.css`). `root.tsx` робить preload для `cyrillic` і `latin`. Підмножини `-ext` браузер довантажує сам, коли на сторінці є такі символи.

- Не повертай Google Fonts: їхній CSS блокує рендер (~750 мс), а CSP (`font-src 'self'` в `app/lib/csp.ts`) його й так заблокує.
- Не прибирай preload: без нього FCP погіршився з 2.4 до 2.7 с.
- Нове накреслення чи гарнітура: woff2 у `app/fonts/` і `@font-face` з `font-display: swap`, не CDN.

### 4. Мінімум JS на першому екрані

- На головній немає `motion`: чанк `react-*.js` насправді містить `motion/react` (~40 КБ gzip). Заставка `PageLoader` анімована на CSS. На внутрішніх сторінках (ідея, гайди, форма ідеї, вхід) `motion` можна.
- Анімації першого екрана роби на `opacity` і `transform`: інші властивості не композитуються і навантажують основний потік.

### 5. Сторонні скрипти вантажаться після `load`

`gtag.js` (~175 КБ) підключається після `load`, у вільний час основного потоку (`GA_SNIPPET` у `root.tsx`). Команди до того чекають у `dataLayer`. Будь-який новий сторонній скрипт (піксель, чат, heatmap) підключай так само і додай його хост у CSP.

### 6. Картинки під розмір показу

Лого показується як 56 px, тому імпортуються `logo-96.webp` і `logo-192.webp`, favicon як `icon-48.png`, а не оригінали на 1024 px. Нова картинка: webp приблизно вдвічі більший за CSS-розмір показу.

### 7. Що свідомо коштує балів і лишається

Заставка `PageLoader` (лендинг і сторінки входу) і `backdrop-blur` на банері згоди коштують 2–3 бали Speed Index. Це рішення про дизайн, його не переглядаємо заради балу. Шукай резерв деінде.

Запобіжники заставки не можна прибирати: CSS-анімація `page-loader-failsafe` ховає оверлей через 2.5 с, навіть якщо JS не виконався, `<noscript>` у `root.tsx` не показує його зовсім, а з `prefers-reduced-motion` його теж немає.

## Як перевірити до мерджу

Локально, у режимі, що відтворює PageSpeed (без GPU):

```bash
cd frontend
npm run build
API_INTERNAL_URL=https://fantasm-dev.naukma.com PORT=4173 npm start

# в іншому терміналі
npx -y lighthouse@13.5.0 http://127.0.0.1:4173/ --only-categories=performance --form-factor=mobile \
  --chrome-flags="--headless=new --use-angle=swiftshader --enable-unsafe-swiftshader" --view
```

Прогони `/` і `/ideas` по три рази й дивись на медіану: Speed Index коливається на кілька балів між запусками. Без прапорців `--use-angle=swiftshader --enable-unsafe-swiftshader` тест іде на GPU твого комп'ютера і показує не те, що бачить PageSpeed.

Орієнтири для локального запуску: бал ≥ 88, TBT близько 0 мс, LCP ≤ 3 с. Локальний SSR ходить у dev-API через інтернет (TTFB +250 мс), тож на проді бал трохи вищий.

Прогін на GPU (той самий запуск без цих двох прапорців) має показати TBT до ~300 мс. Це разова компіляція шейдерів при старті сцени. Секунди TBT означають, що сцена стартує не через `whenIdleAfterLoad`.

Після деплою перевір прод: [PageSpeed для ideas.naukma.com](https://pagespeed.web.dev/report?url=https%3A%2F%2Fideas.naukma.com%2F).
